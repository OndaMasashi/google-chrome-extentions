# Gemini Notebook へのリブランド対応（拡張が無反応になった不具合の修正）

## 対象

- `nlm-toolkit/manifest.json`
- `nlm-toolkit/content.js`
- `nlm-toolkit/README.md`
- `README.md`（リポジトリルート）

## 変更内容

### 1. 対応ドメインの追加（本件の直接原因）

`matches` に `https://notebook.google.com/*` を追加。旧 `notebooklm.google.com` も互換のため残置。

### 2. 日付フォーマットの拡張

`YYYY/MM/DD` 固定だったパーサを複数フォーマット対応に置き換え。
`YYYY/MM/DD` / `YYYY-MM-DD` / `YYYY年M月D日` / `Mon D, YYYY` / `D Mon YYYY` を検出する。
月名は先頭3文字で照合し、月1-12・日1-31の範囲検証を通したものだけ採用する。

### 3. カード検出の縮退モード

ノートブックカードの識別子を `a[href*="/notebook/"]` から
`a[href*="/notebook/"], a[href*="/notebooks/"], [data-notebook-id]` に拡張。
さらに、ページ内にこれらが1件も存在しない場合（SPA が a タグを使わない構成に変わった場合）は
リンク条件を外し、日付テキストのみで探索する縮退モードに自動で切り替わる。

### 4. アンカー探索の改善と浮動パネルへのフォールバック

XPath の `contains(text(), ...)` による探索をやめ、`button` / `[role="button"]` /
`[role="combobox"]` / `[role="listbox"]` を対象に、ラベル完全一致を優先する走査に変更。
ラベル候補も日英で拡充（「最近使用したもの」「更新日順」「Newest」等）。
6回試行しても見つからない場合は、画面右下の浮動パネルとして UI を注入する。

### 5. 診断ログ

UI を注入できない状態が続いたとき、URL・日付要素数・日付サンプル・ノートブックリンク数・
ボタンラベル一覧をコンソールに出力する。次回 DOM が変わったときの原因特定を高速化するため。

### 6. 注入リトライをタイマー化

旧実装の再試行は MutationObserver 依存だったため、一覧の描画が終わって DOM の変化が止まると
再試行が発火せず、浮動パネルへのフォールバックに到達しない欠陥があった。
800ms 間隔・最大40回（約32秒）の定期リトライを追加し、注入成功で自動停止するようにした。

### 7. その他

- SPA 遷移時に注入済み UI を破棄してから再注入するよう修正（旧実装は遷移後も古い DOM 参照が残る余地があった）
- 注入済みの場合は再探索せず件数ラベルのみ更新するよう整理
- 自前で注入した UI が探索対象に混入しないよう除外処理を追加
- 名称を「NotebookLM Toolkit」→「Gemini Notebook Toolkit」に変更、version 2.0.0 → 2.1.0

## 理由

2026年7月16日に Google が NotebookLM を「Gemini Notebook」へ改称し、
ドメインが `notebooklm.google.com` → `notebook.google.com` へ移行した（8月1日までに全リクエストがリダイレクト）。
manifest の `matches` が旧ドメインのみだったため content script がロードされず、拡張が完全に無反応になっていた。

同時に UI 側の DOM も変わっている可能性があるため、日付表記・カード構造・ボタンラベルの
いずれが変わっても動くよう耐性を上げた。

## 検証状況

- **確定（外部の実測）**: `https://notebooklm.google.com/` が `notebook.google.com` に
  リダイレクトすることをブラウザで確認済み。これが無反応の直接原因。
- **仮説検証のみ（モックページ）**: 新UIを模した HTML を Chrome で読み込み、
  和暦風/英語の日付パース・ソート昇降順・タイトルフィルタ・リンクなし構成での縮退モード・
  アンカー不在時の浮動パネルフォールバックが動作することを確認。コンソールエラーなし。
  ただしこれは自作の代替物であり、本番 DOM での動作を保証しない。

## 残作業

- **実 DOM での動作確認が未実施**。Claude Code が操作するブラウザは Google のログインを
  ブロックされるため、ログイン後の一覧画面を直接検証できていない。
  ユーザー環境での確認が必要。
- 一覧の日付が「2日前」等の**相対表記**に変わっている場合は未対応（診断ログで検知可能）。
  必要なら相対表記のパースを追加する。
- Gemini アプリ側（`gemini.google.com` のサイドバー内ノートブック）は対象外のまま。
