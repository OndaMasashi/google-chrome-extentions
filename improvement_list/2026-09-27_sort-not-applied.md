# 並び替えが効かない不具合の修正（初回クリック反転 / 再描画で解除）

## 対象

- `nlm-toolkit/content.js`
- `nlm-toolkit/manifest.json`
- `nlm-toolkit/README.md`

## 調査で分かったこと

ユーザー環境（313件のノートブック）の実 DOM を Console 経由で計測した結果:

```text
日付要素: 313 / 単位数: 313 / コンテナ: div.project-grid-container
コンテナdisplay: contents / 仮想スクロール: false
カード例: project-button.project-button.luminous-ui
カードposition: static / transform: none / order: 0 / gridRow: auto
並べ替え直後: true / 1.5秒後: true
```

- 検出（日付・カード・コンテナ）は**すべて正常**。313件を正しく認識している
- `appendChild` による並べ替えは **DOM に反映され、1.5秒後も保持される**
- したがって「CSS レイアウトで DOM 順が無視される」「Angular が即座に戻す」「コンテナ誤検出」はいずれも**否定された**
- 上部バーに並び替えのテキストボタンは存在せず（操作系ラベルは「設定」「グリッド表示」「リスト表示」「新しいノートブック」等）、浮動パネルへのフォールバックは設計通りの動作

残る原因はボタンのクリック経路側にあると判断し、コードを精査して確実なバグを2件特定した。

## 変更内容

### 1. 初回クリックで並び順が反転していた（確定バグ）

旧実装のクリックハンドラは、`performSort` を呼ぶ**前**に無条件で `dataset.order` をトグルしていた。
初期表示は `desc`（ラベル「作成日順 ↓」）なので、**初回クリックで昇順（最古が先頭）が適用される**。
ラベルの矢印と実際の並び順が初回だけ食い違い、「並び替えがおかしい／効いていない」と見える。

未ソート時（`sortState === null`）はトグルせずラベル通りの順を適用し、2回目以降でトグルするよう修正。

### 2. 一覧の再描画で並び順が解除される（防御的修正）

並べ替えは1回きりの `appendChild` で、その後 SPA 側が再描画すると元の順に戻っていた。
`sortState`（適用中の並び順）を保持し、DOM の変化を検知するたびに再適用する方式へ変更。

再適用は `applySortTo` を**冪等**にすることで安全にした。現在の並びが目的の並びと一致していれば
DOM を一切触らずに `false` を返すため、自分の並べ替えが MutationObserver を再発火させても1周で収束する。

### 3. 機能していなかった `isSorting` ガードを削除

MutationObserver のコールバックは非同期（マイクロタスク）で呼ばれるため、
同期的に `true`→`false` と切り替えていた `isSorting` はコールバック到達時点では必ず `false` に戻っており、
自己発火の抑止として機能していなかった。#2 の冪等化で不要になったため削除。

### 4. ログの改善

クリック時に `ソート実行: 作成日降順 / 対象313件 / DOM変更あり` の形式で、
順序・件数・DOM を実際に変更したかを出力する。コンテナ要素も併せて出力し、次回の切り分けを速くする。

### 5. その他

- 件数ラベルの更新と並び順の再適用を `refresh()` に集約し、`collect()`（全文探索）の重複呼び出しを削減
- UI 注入直後に `refresh()` を呼び、静的なページでも件数が即座に表示されるようにした
- version 2.1.0 → 2.2.0
